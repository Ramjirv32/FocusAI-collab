# FocusAI Installation & Database Issues - Fixed

## Date: 2025-12-29

### Issues Identified and Fixed

#### 1. **Database Not Storing Data in .deb Package Installation**

**Root Cause**: The systemd services were not loading environment variables from `.env` files, causing the backend to fail connecting to MongoDB and storing data.

**Fix Applied**:
- Updated `install/install.sh` to add `EnvironmentFile` directive to all three systemd services:
  - `focusai-backend.service` → Loads `/opt/focusai/focuaibackend/.env`
  - `focusai-frontend.service` → Loads `/opt/focusai/Frontend/.env`
  - `focusai-ai.service` → Loads `/opt/focusai/ai/.env`

**Files Modified**:
- `/install/install.sh` (lines 550, 572, 595)

---

#### 2. **Frontend Hardcoded API URLs**

**Root Cause**: Frontend was using hardcoded `http://localhost:5001` URLs instead of reading from environment variables, causing connection failures when installed via .deb package.

**Fix Applied**:
- Created centralized API configuration file: `Frontend/src/config/api.ts`
- Updated critical frontend files to use `API_BASE_URL` from config:
  - `Frontend/src/pages/Index.tsx`
  - `Frontend/src/context/AuthContext.tsx`
  - `Frontend/src/services/activityDataService.js`
- Added `VITE_AI_SERVER_URL` to `Frontend/.env.example`

**Files Modified**:
- `Frontend/src/config/api.ts` (NEW)
- `Frontend/src/pages/Index.tsx`
- `Frontend/src/context/AuthContext.tsx`
- `Frontend/src/services/activityDataService.js`
- `Frontend/.env.example`

---

#### 3. **AI Server Using "unknown@example.com" Instead of Real Email**

**Root Cause**: The AI server's `analyze_and_store_productivity` function received `email: None` and defaulted to `"unknown@example.com"`, causing productivity summaries to be stored with wrong email.

**Fix Applied**:
- Modified `ai/main.py` to extract email from fetched user data if not provided as parameter
- Added email extraction logic after fetching `user_data_list`

**Files Modified**:
- `ai/main.py` (lines 1166-1168)

---

### AI Provider Selection (Already Working Correctly)

The AI chat system **already correctly** uses only the selected provider:

**How It Works**:
1. User selects provider in "AI Intelligence Settings" dialog (Groq or Ollama)
2. Frontend sends selection to backend `/api/settings/ai-config`
3. Backend saves to:
   - `~/.focusia/config.json`
   - `.env` files in all three services
4. `aiProvider.js` checks `process.env.AI_PROVIDER`:
   - If `'groq'` → Uses Groq API only
   - If `'ollama'` → Uses local Ollama only

**No changes needed** - the system is working as designed!
